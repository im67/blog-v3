## 因为贫穷
众所周知，虽然现在云服务器相当普及，但是其价格永远是不可磨灭的痛，特别是对一个普普通通个人开发者来讲，云服务器的价格仍然感到肉疼。笔者的博客站就在一个1核2g的服务器上小心翼翼的运行着，跑两个Docker的Nodejs服务。



有一天笔者在云服务器上拉取了前端Git库的代码后，执行build命令，等待后就会出现：

> rendering chunks...  Killed!
>

多次执行偶尔能成功，我开始怀疑事情没有那么简单，直觉告诉我应该是和硬件配置有关。果不其然当我在Vite仓库的Issue中搜索时，有人遇到了类似的问题，发生了OOM。



虽说能用钱解决的问题就不是问题，但是看到升级服务器内存的价格时，我还是觉得不太值得，这时候我想起了windows系统中的虚拟内存，然后突然想到某节大学课堂上的某个知识点：交换文件。



## 扩展内存
Swap是Linux下的交换文件，类似于windows上的虚拟内存。物理内存不足时，系统可以把一些不常用的程序放入交换分区，从而弥补内存不足的情况。用硬盘来负责这部分工作显然会降低IO效率，但是对于我的情况来讲无所谓，所以这里进行交换文件的扩展。



使用**dd**命令创建交换文件。其中**bs**是数据块大小，**count**是数据块的数量。交换文件的总大小等于数据块大小乘以数量。



这里需要注意的是，数据块大小应该比可用内存小，否则可能会报错。



> sudo dd if=/dev/zero of=/swapfile bs=128M count=32
>

上面命令创建了一个4GB的交换文件。



接下来更改交换文件的读取权限和写入权限

> sudo chmod 600 /swapfile
>



然后设置系统的交换区域

> sudo mkswap /swapfile
>



将交换文件添加到交换空间，然后立即使用交换文件

> sudo swapon /swapfile
>



测试一下是否成功

> sudo swapon -s
>
> 
>
> 输出/swapfile信息即可
>



最后通过编辑/etc/fstab文件，在系统启动时就启用交换文件

> sudo vim /etc/fstab
>
> 
>
> 添加以下内容到末尾新行，保存退出
>
> 
>
> /swapfile swap swap defaults 0 0
>



然后重新执行vite的build命令，一切运行正常。
