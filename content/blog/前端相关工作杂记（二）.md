## Monorepo
Monorepo本质上是将多个项目在同一个代码仓库中管理，这些项目通常是有关联的，本质上是为了简化大型项目构建时的项目复杂度。他有以下优点：
1. 共享代码可以在同一个仓库中维护。
2. 可以用同一套代码规范，CI/CD流程，测试和代码检查工具。
3. 可以将不同工具的同一批修改在一个提交中完成。
4. 容易对代码整体进行处理。

对应的，也会产生一些缺点：
1. 仓库项目会变臃肿，特别是会产生很多提交历史记录。
2. 通常需要额外的脚本进行不同模块和功能的构建管理。
3. 权限控制颗粒度会变的很粗。
4. 工具要求高。
   
总体来讲，收益是大于缺点的，现在很多前端工具库都使用monorepo模式进行管理，例如Vue3的代码仓库。

## 正向代理和反向代理

### 正向代理
正向代理是客户端代理，客户端知道目标服务器，但是其请求通过代理服务器发送给目标服务器，目标服务器只能解析到是代理服务器发送的请求，看不到真实的客户端。常见的形式就是vpn等形式。

### 反向代理
反向代理是服务端代理，客户访问的是代理服务器，而不是背后的真正的服务器。通常Nginx可以用反向代理来实现负载均衡，隐藏内部服务架构，缓存加速，SSL处理等。

## Nodejs中间件
一开始这个问题给我搞蒙了, 我第一反应是: Nodejs为什么有中间件，后来意识到这里的Nodejs中间件是指诸如Express, Koa这类依托于Nodejs的服务端框架的中间件思想。

中间件本质上就是处理在接收到请求后，到最终响应之前，在中间对请求/响应进行处理的一系列函数。这个Koa开发中很熟悉，洋葱圈模型就是通过一层一层的中间件完成的，一般中间件可以拿到上一级中间件处理后的结果，然后进行处理传递给下一级的中间件，也可以直接通过res.xxx等方法直接返回，不通过后续中间件处理。

非常熟悉的问题，但是被一开始的问法问懵了。

## 虚拟列表的实现
问到渲染优化, 大多数时候都要提一嘴虚拟列表的实现。大多数的前端引起的渲染类性能问题基本上都是因为DOM节点太多导致的页面性能下降, 所谓的虚拟列表就是通过解决这个问题来达到性能提升的目的。虚拟列表的主要思想就是: 仅仅处理视窗可见部分的DOM节点, 对于不可见部分不进行渲染。


### 定高虚拟列表的实现
根据这个思想, 比较容易构建出一个简单的虚拟列表的实现:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>虚拟列表的实现</title>
  <style>
    * {
      padding: 0;
      margin: 0;
    }

    .container {
      position: relative;
      overflow-y: auto;
      height: 500px;
      /* width: fit-content; */
      background: #ccc;
    }

    .placeholder {
      position: absolute;
      width: 1px;
    }

    #viewport {
      position: absolute;
      height: 100%;
    }
  </style>
</head>
<body>
  <div id="con" class="container">
    <ul id="viewport"></ul>
    <div id="holder" class="placeholder"></div>
  </div>
  <script>
    // 设置行高固定 30px
    const listHeight = 30;
    // 模拟10w条列表数据
    const data = new Array(100000).fill(0).map((_, i) => i);
    const $ul = document.querySelector("#viewport");
    // #region - 设置初始的渲染内容
    const defaultDataEnd = Math.floor(500 / 30);
    data.slice(data, defaultDataEnd).forEach((content) => {
      const $li = document.createElement("li");
      $li.textContent = content;
      $li.style.height = `${listHeight}px`
      $ul.appendChild($li)
    })
    // #endregion

    // 生成占位元素, 按照高度进行计算
    const $holder = document.querySelector("#holder");
    $holder.style.height = listHeight * data.length + 'px'

    // #region - 添加事件, 记录滚动条位置
    const $container = document.querySelector("#con");
    $container.addEventListener("scroll", (e) => {
      const scrollTop = e.target.scrollTop;
      const dataStart = Math.ceil(scrollTop / listHeight);
      const dataEnd = Math.floor((scrollTop + 500) / listHeight);
      const dataRange = data.slice(dataStart, Math.min(data.length + 1, dataEnd + 3));
      // 更新时清空我们的viewport, 将新的数据渲染进去
      $ul.innerHTML = '';
      $ul.style.top = scrollTop + 'px';
      dataRange.forEach((content) => {
        const $li = document.createElement("li");
        $li.textContent = content;
        $li.style.height = `${listHeight}px`
        $ul.appendChild($li)
      })
    });
    // #endregion
  </script>
</body>
</html>
```
通过控制台检查元素就能够看到, 每次只有个别数量的节点被创建, 提升了渲染效率。

不过上面这个实现在实际使用中就会发现一个问题: 滚动效果似乎是"跳变"的, 也就是说, 随着滚动, 数据一条一条的完整出现, 似乎没有滚动遮挡一半的中间状态。从实现中可以发现造成这个问题的原因: 我们向viewport中添加元素, 然后修改viewport的定位, 且定位top总是和滚动距离保持一致, 所以出现了"跳变"。

此时一个可以考虑的优化点是: 既然元素是定高的, 我们显然可以直接向元素内插入目标节点, 只需要修改每个条目元素的top值在他该在的地方, 滚动就会变的更加自然。基于此, 我们可以完成改进版本的虚拟列表实现: 

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>虚拟列表的实现</title>
  <style>
    * {
      padding: 0;
      margin: 0;
    }

    .container {
      position: relative;
      overflow-y: auto;
      height: 500px;
      /* width: fit-content; */
      background: #ccc;
    }

    .placeholder {
      position: absolute;
      width: 1px;
    }

    #viewport {
      position: relative;
    }
  </style>
</head>
<body>
  <div id="con" class="container">
    <div id="holder" class="placeholder"></div>
    <div id="viewport"></div>
  </div>
  <script>
    // 设置行高固定 30px
    const listHeight = 30;
    // 模拟10w条列表数据
    const data = new Array(100000).fill(0).map((_, i) => i);
    // #endregion

    // 生成占位元素, 按照高度进行计算
    const $holder = document.querySelector("#holder");
    $holder.style.height = listHeight * data.length + 'px'

    // #region - 添加事件, 记录滚动条位置
    const $container = document.querySelector("#con");
    // 为了方便元素的添加和替换, 这里向占位视窗元素内进行节点替换
    const $viewport = document.querySelector("#viewport");
    $container.addEventListener("scroll", (e) => {
      const target = e.target;
      const scrollTop = target.scrollTop;
      const dataStart = Math.floor(scrollTop / listHeight);
      const dataEnd = Math.ceil((scrollTop + 500) / listHeight);
      const dataRange = data.slice(dataStart, dataEnd);
      const nodes = dataRange.map((item, index) => {
        const $div = document.createElement('div');
        $div.textContent = item;
        $div.style.top = (dataStart + index) * 30 + 'px';
        $div.style.position = 'absolute';
        return $div;
      })
      $viewport.replaceChildren(...nodes);
    })
    // TODO: 为了方便, 这里通过触发scroll事件完成初始渲染的处理, 也可以通过将渲染方法单独定义, 然后开始时执行一次
    $container.scroll({ top: 1 });
    // #endregion
  </script>
</body>
</html>
```

通过以上优化, 我们得到了一个滚动更加平滑的虚拟列表加载的优化版本。不过还有一些细节点可以优化, 例如滚动过快可能出现上下方空白的情况, 这里可以通过额外预加载的方式进行处理, 上下视窗外多渲染一部分内容。这里不再做详细赘述。

### 不定高度虚拟列表

以上虚拟列表的实现都有一个基本前提, 就是渲染的数据高度是固定的, 这样可以方便计算, 每个条目出现的位置都是确切可知的。但是实际上很多情况下, 由于数据的多变性, 难以确切的知道最终数据渲染之后的状态, 那么如何设计不确定高度的虚拟列表。

思考之后比较容易得到大致的方向, 就是通过预估高度先建立渲染框架, 然后在实际创建元素之后, 不断的调整实际高度, 最终建立起整个渲染区域，复杂的是，这里会出现一些边缘问题需要进行处理。

和上面的定高模式一样, 初始时我们先根据预估高度进行渲染, 建立起大致的渲染框架:

```javascript
    // 设置行高固定 50px
    let simulatedListHeight = 50;
    // 额外渲染
    const extraData = 5;
    // 模拟10w条列表数据
    const data = new Array(100000)
      .fill(0)
      .map((_, i) => `${i}. `.padEnd(
        Math.floor(Math.random() * 500) + 1, String.fromCharCode(97 + Math.floor(Math.random() * 26))
      )
      );
    // #endregion
    // rowMap用来记录每一行的高度
    const rowMap = new Map();
```

接着我们监听滚动事件, 处理事件。首先我们需要知道"当前滚动区域需要渲染哪些数据", 我们的设计中会记录实际的每一行高度, 那么当前需要渲染的数据开始值就是高度值累加后结果距离scrollTop最近的那一条, 我们定义我们的查找函数:

```javascript
// 计算索引i之前的所有高度之和, 没有实际渲染的用模拟高度代替
const calcSumHeight = (i) => {
  let sum = 0;
  for (let k = 0; k < i; k++) {
    sum += rowMap.get(k) || simulatedListHeight;
  }
  return sum;
}

// 二分查找找到左侧第一个小于scrollTop的索引值
const getDataStart = (scrollTop) => {
  let l = 0, r = data.length;
  while (l < r) {
    const half = Math.floor((l + r) / 2);
    if (calcSumHeight(half) < scrollTop) {
      l = half + 1;
    } else {
      r = half;
    }
  }
  return l;
}
```

接着我们按照上面固定高度虚拟滚动的思路进行事件监听:

```javascript
    $container.addEventListener("scroll", (e) => {
      const target = e.target;
      const scrollTop = target.scrollTop;
      // 获取到开始数据
      const dataStart = getDataStart(scrollTop);
      // 获取到渲染开始数据(一般上下渲染一定数量的额外元素, 避免滚动时出现上下空白)
      const renderStart = Math.max(0, dataStart - extraData);
      let renderItemHeight = 0;
      const dataRange = data.slice(renderStart);
      let startTop = calcSumHeight(renderStart);
      const children = Array.from($viewport.childNodes);
      for (const [index, item] of dataRange.entries()) {
        let isNew = false;
        let $div = children.shift();
        // 尽量复用已有节点, 如果没有再去创建, 这在vue等框架中很容易实现
        if (!$div) {
          $div = document.createElement('div');
          isNew = true;
        }
        $div.textContent = item;
        $div.style.position = 'absolute';
        $div.style.top = startTop + 'px';
        const rowIndex = renderStart + index;
        if (isNew) {
          $viewport.appendChild($div);
        }
        const { height } = $div.getBoundingClientRect();
        // 插入dom后获取实际的元素高度, 然后更新map
        rowMap.set(rowIndex, height);
        // 更新下一个插入元素的top值
        startTop += height;
        // renderItemHeight控制渲染条数, 当渲染的总高度大于阈值后, 渲染停止
        renderItemHeight += height;
        if (renderItemHeight > 1500) {
          break;
        }
      }
      // 如果有多余的dom节点, 需要移除
      children.forEach((r) => {
        r.remove();
      })
    })
```

一个基本的不定高度的虚拟列表基本就实现了, 接下来我们需要考虑以下细节：

1. 我们数据预估都是根据开始时设置的simulatedListHeight进行计算的, 为了使数据更加精准, 我们需要调整simulatedListHeight，以便后续预估更加精准。
2. 我们初始时，为了撑开滚动区域的$holder元素的高度是按照simulatedListHeight * 数据总量进行计算的, 随着数据变化，我们也需要更新$holder的高度。

因此, 我们定义如下方法:

```javascript
const updateSimulatedListHeight = () => {
  const total = [...rowMap.values()].reduce((prev, curr) => {
    return prev + curr;
  })
    simulatedListHeight = Math.floor(total / rowMap.size);
}

const updateHolderHeight = () => {
  const height = calcSumHeight(data.length);
  $holder.style.height = height + 'px';
}
```

在数据DOM元素插入后, 我们需要调用更新方法。

按照上面的实现，在实际使用虚拟列表的过程中，如果出现大距离的滚动，然后进行向上滚动时，会发现出现滚动"跳变"，很容易理解这个问题的原因：在大范围的跳动时，渲染元素的位置是基于高度预测的，当渲染之后，预测高度变成实际高度，势必会发生定位偏移的情况，所以看起来就是上下抖动，基于此，我们需要进行"定位修正"。

定位修正其实就是在元素渲染之后，计算渲染后和渲染前，第一个可见元素的位移偏差，然后在渲染结束后修改scrollTop，使滚动条还是在"原先的位置上", 根据此, 我们可以设计我们的代码:

```javascript
// 在scroll事件开始时执行, 获取scrollTop位置第一个可见元素的top
const _startTop = calcSumHeight(dataStart);

// 执行渲染

//获得渲染结束后的上面提到的可见元素的top值, 并计算差值, 然后修正
let afterTop = calcSumHeight(dataStart);
const diff = afterTop - _startTop;
if (diff !== 0) {
  target.scrollTop += diff;
}
```

最终我们就能得到我们的完整scroll事件处理函数:

```javascript
$container.addEventListener("scroll", (e) => {
  const target = e.target;
  const scrollTop = target.scrollTop;
  const dataStart = getDataStart(scrollTop);
  const renderStart = Math.max(0, dataStart - extraData);
  let renderItemHeight = 0;
  const dataRange = data.slice(renderStart);
  let startTop = calcSumHeight(renderStart);
  const _startTop = calcSumHeight(dataStart);
  const children = Array.from($viewport.childNodes);
  for (const [index, item] of dataRange.entries()) {
    let isNew = false;
    let $div = children.shift();
    if (!$div) {
      $div = document.createElement('div');
      isNew = true;
    }
    $div.textContent = item;
    $div.style.position = 'absolute';
    $div.style.top = startTop + 'px';
    const rowIndex = renderStart + index;
    if (isNew) {
      $viewport.appendChild($div);
    }
    const { height } = $div.getBoundingClientRect();
    rowMap.set(rowIndex, height);
    startTop += height;
    renderItemHeight += height;
    if (renderItemHeight > 1500) {
      break;
    }
  }
  children.forEach((r) => {
    r.remove();
  })
  updateSimulatedListHeight();
  updateHolderHeight();
  let afterTop = calcSumHeight(dataStart);
  const diff = afterTop - _startTop;
  if (diff !== 0) {
    target.scrollTop += diff;
  }
})
```

至此, 不定高的虚拟列表也实现了，但是但是但是，其实还是有比较大的优化空间，例如对于calcSumHeight方法，作为整个虚拟列表的基础计算方法，在很多地方都有使用，但是他其中包含一个二分查找加一个循环计算, 对于大数据量的处理还有优化的空间，我们可以采取分块和建立缓存的形式避免重复计算，另外可以使用更利于查找和计算的树结构，这部分内容留个坑，以后再补一补。
