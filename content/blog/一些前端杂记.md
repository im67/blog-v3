## 控制并发请求
这个问题在挺久以前面试的时候遇到过，当时答的不太好，正好近期又有需求有类似的功能，场景是有一个上传的功能，支持多文件上传，用户选中多个文件执行上传之后，最终呈现（或者说数据设计）是每一个文件对饮表格的一行数据，所以采用实际请求时一个文件进行一次上传的方式，此时就会产生一个问题：当文件比较多的时候，可能会有数十个请求同时进行，需要一定的限制，每次最多允许n个请求同时处理，前端控制调用。实现如下：

```typescript
const fetchWithLimit = (reqs, limit) => {
  return new Promise((resolve, reject) => {
    const max = Math.min(reqs.length, limit);
    //存放所有请求完成之后的结果
    const result = [];
    const runReqs = new Set();
    let count = 0;
    const genReq = (index) => {
      // 在fetch的回调中在此添加fetch, 递归调用
      const req = _fetch(reqs[index]).finally(() => {
        runReqs.delete(req);
        result.push(req);
        if (count === reqs.length) {
          // 最终的结果返回在这里进行处理
          // 这里返回了所有请求的promise
          // 也可以获取到结果直接返回结果
          // 视需求而定
          resolve(result);
        } else {
          genReq(count);
          count++;
        }
      });
      runReqs.add(req);
    }
    //首先处理能够全部并发的reqs
    for (let i = 0; i < max; i++) {
      count++;
      genReq(i);
    }
  })
}
```

## 滚动边界行为
以前也遇到过这个问题，但是怎么解决的给忘了。所谓的滚动边界其实就是，当一个可滚动元素内还有一个可滚动元素的时候，内部的可滚动元素滚动到边界，也就是到头之后，接着会触发祖先元素中的可滚动元素的滚动行为。在某些场景下这个行为还是比较恼人的，解决方法就是一个简单的CSS属性：

```css
overscroll-behavior: auto; /* 默认 */
overscroll-behavior: contain; /* 目标值 */
overscroll-behavior: none;
```

contain表示滚动到边界的行为不变，祖先滚动元素不会受到滚动链的影响，也就是说到达滚动边界之后不会触发祖先元素的滚动。



none则会取消滚动到边界的默认行为，并且取消滚动链影响。



不仅如此，在移动开发的时候会有一些默认的滚动行为可以通过此方式组织。例如在Android上的Chrome，当滚动超过顶部边界，行为会变成下拉刷新页面，此时可以通过设置为none阻止行为。更多用法可以[点击这里](https://developer.mozilla.org/zh-CN/docs/Web/CSS/overscroll-behavior)查看。



## Vue中一次页面卡死
在最近一次项目中，完成开发推送到线上的时候，测试发现有一个弹窗功能打开后页面会卡死，而且无法恢复，只能刷新页面，而且屡试不爽。初步看到这个问题时，心里大概有数可能是某个地方发生了循环，导致主线程一直占用，但是这类问题比较难以排查，从开发过程中没有遇到过类似的情形可以推断，存在于业务代码中的硬性错误逻辑的概率不大，很可能是正式环境和测试环境的差异引起的问题，经过不断地对比，发现在使用Element组件的tableV2时，使用cellRender定义了单元格的内容展示

```javascript
node = h('div', null, [
  h('div', null, "自定义url"),
  h('div', { class: "text-xs opacity-60 pt-1" }, click_url),
])
```

其中展示了url内容，在开发文档的约束中，click_url的数据格式是字符串格式，但是在线上因为部分数据的处理，导致click_url的数据格式变成了数组格式，这导致click_url作为一个引用对象传入后，在虚拟dom的构建中会变成node节点类型，而错误的触发渲染（因为对其改变会触发vue渲染，而渲染时又会改变click_url）。因此这里需要对格式进行处理，针对性的代码处理如下

```javascript
node = h('div', null, [
  h('div', null, "自定义url"),
  h('div', { class: "text-xs opacity-60 pt-1" }, Array.isArray(click_url) ? click_url.join(',') : click_url),
])
```

如上，解决。



## Select组件的before-change
这其实是一个相对简单的场景，在需求实现的过程中，有一个场景如此：现在有一个下拉选择组件ElSelect，在这个组件发生变化的时候，会影响后续表单中的某些默认值变化，该操作需要用户确认，因此我们需要有如下流程：执行select选择 -> 异步询问用户是否决定修改 -> 不执行修改(取消)或者执行修改(确认)。但是实际上大多数的组件仅提供change事件，也就是在选择发生之后进行处理，而无法细粒度到数值改变之前还是之后。因为vue的双向绑定的特性，往往这样的需求实现需要将已经改变为最新的值改变回来，以此模拟"终止改变"的效果，这样就需要处理改变前/后逻辑，相对繁琐。



综上，一个比较好的处理方式应当是建立事件before-change，该事件作用在change之前，并且before-change和change事件在执行上严格前后顺序，可以中断。基于Element组件，可以给出如下的封装：

```typescript
<template>
  <div class="select-with__before-change" >
    <el-select :model-value="_selectValue" @change="selectChange" v-bind="$attrs">
      <el-option label="first" :value="1" />
      <el-option label="second" :value="2" />
    </el-select>
  </div>
</template>

<script lang="ts">
//取消属性继承, 将属性直接传递到内部的ElSelect中进行处理
export default {
  inheritAttrs: false
}
</script>

<script lang="ts" setup>
import { ref, useAttrs, watch } from "vue";
const props = defineProps(['modelValue']);

/**
 * 注意, 这里不能将beforeChange加入到, 否则将无法检测到组件是否绑定了
 * 对应事件, 该问题也经常被讨论, 详见https://github.com/vuejs/core/issues/8082
 */
const emit = defineEmits(['update:modelValue', 'change']);

const _selectValue = ref<any>('');

// 保证在实际的modelValue变化时能够同步至Select组件的modelValue
watch(() => props.modelValue, (n) => {
  _selectValue.value = n;
}, { immediate: true })

const attrs: any = useAttrs();

// 在原本ElSelect组件的change事件中处理组件
// 如果有onBeforeChange属性, 则执行, 并且支持异步, 以便可以终止该操作
// 递交给函数执行的参数是数组, 分别是要改变的新值和当前的旧值
// 如果值发生了改变, 改变数值, 并触发组件的change事件
const selectChange = async (value: any) => {
  if (attrs.onBeforeChange) {
    try {
      await attrs.onBeforeChange([value, props.modelValue]);
      valueChange(value);
    } catch(e) {
      return ;
    }
  } else {
    valueChange(value);
  }
}

const valueChange = (value: any) => {
  emit("update:modelValue", value);
  emit("change", value);
}

</script>
```

至此我们可以通过引用组件并且绑定before-change事件完成整个功能。



这里有一个细节值得讨论一下，我们知道Vue中事件与属性其实绑定传递写法不同，这与react有差异。但实际上属性和事件并没有本质区别：事件不过是一个函数类型的属性，因此在Vue的相关讨论中，有部分人其实建议二者合并，降低复杂度。在完成本功能时，其实现有的Vue在非API设计的情况下进行功能组装时确实不大方便。按照Vue的文档规范，我们的beforeChange事件当然需要在emit中声明，但是声明后无法知晓"组件实例上究竟有没有绑定这个事件"这件事，因为没有任何地方记录。而且emit还有一个问题就是没有返回值，这意味着我们必须用参数传递的形式实现异步。因此我们在上述代码中的解决方法是，不在emit中声明，这样就可以在$attrs属性上检测到，然后执行对应逻辑。



所以，个人认为将二者区分可能确实没有必要，需要进行更多的处理。



## 深比较两个对象的异同
前几天同事丢给我一个数据，是从第三方获取到的，因为太复杂，为了简便他存储的方式就是把这个巨大的JSON转化成字符串，然后前端转成对象进行数据处理。这真的是一个很复杂的数据，因为数据库中text类型的字段都无法完全容纳这个JSON字符串。



笔者拿到数据进行数据展示后发现，有的时候会出现数据"重复"的情况，一开始想到既然数据重复，那么直接去重即可，直接对字符串进行比较，发现明明直观上感觉到的两个相同的对象字符串比较却是false，说明其中的某些字段可能是不相同的，于是我需要知道哪些字段不相同，引起的比较有问题。所以这就涉及到一个深比较，记录相异字段的问题，笔者构建的代码如下：

```typescript
const findDiffProperties = (obj1, obj2) => {
  let diff = {};

  for (let key in obj1) {
    if (_.isEqual(obj1[key], obj2[key])) {
      continue;
    }

    if (_.isObject(obj1[key]) && _.isObject(obj2[key])) {
      const nestedDiff = findDifferentProperties(obj1[key], obj2[key]);
      if (!_.isEmpty(nestedDiff)) {
        diff[key] = nestedDiff;
      }
    } else {
      diff[key] = obj1[key];
    }
  }

  return diff;
}
```

从而得到是否有不相同的属性。



## 几个比较无聊的问题
第一个问题是给定一个字符串，输出每个字符，当输出到最后一个字符的时候再重头开始。紧接着还给出了一个示例：

```typescript
const bar = loopString('abcd');
console.log(bar(),bar(),bar(),bar(),bar())  // a,b,c,d,a
```



一看就知道是个高阶函数的问题，最简单的解决方法是：

```typescript
const loopString = (str) => {
  //保存字符串
  let temp_str = str;
  // 闭包保存当前字符的index
  let index = 0;
  return () => {
    let len = temp_str.length;
    const char = temp_str[index];
    index++;
    if (index === len) index = 0;
    return char; 
  }
}
```



当然我们也可以稍微复杂一点。输出到最后一个字符再从头开始，这看起来就像是一个圈，所以想到了循环链表：

```typescript
const loopString = (str) => {
  //定义一个函数生成链表节点
  const genNode = (val, next = null) => {
    return {
      val, next
    }
  };
  let temp = genNode(str[0]);
  //储存首节点
  let start = temp;
  //依次生成各个链表节点
  for (let i = 1; i < str.length; i++) {
    const node = genNode(str[i]);
    temp.next = node;
    temp = node;
  }
  //首尾相接
  temp.next = start;
  return () => {
    const val = start.val;
    start = start.next;
    return val;
  }
}
```



第二个问题是实现链式计算器，举例

```typescript
calc(1).add(8).minus(3).mulit(10).div(2).getValue() //30
```



其实就是链式调用，返回自身对象的问题，上手就是一个类。

```typescript
class Calc {
  value = 0;

  constructor(val) {
    this.value = val;
    return this;
  }

  add(val) {
    this.value += val;
    return this;
  }

  minus(val) {
    this.value -= val;
    return this;
  }

  mulit(val) {
    this.value *= val;
    return this;
  }

  div(val) {
    this.value /= val;
    return this;
  }

  getValue() {
    return this.value;
  }
}


const calc = (n) => {
  return new Calc(n)
}

```



第三个问题，实现一个累加函数的功能，举例

```typescript
sum(1,2,3)(2).valueOf() // 1 + 2 + 3 + 2
```



实际上也是个高阶函数的问题。

```typescript
function sum() {
  // args存储所有进入的参数
  const args = [...arguments];
  // returnCb用于接受后续参数, 并且返回自身, 以便累计记录
  function returnCb() {
    const _args = [...arguments];
    args.push(..._args);
    return returnCb
  }
  // valueOf用于求和输出结果
  returnCb.valueOf = function () {
    return args.reduce((prev, curr) => {
      return prev + curr
    }, 0)
  }
  return returnCb;
}
```



综上，其实是一些比较无聊的问题。



## Echarts中的Tree的更新
Echarts中的tree类型的图，本身支持展开/折叠操作，实际有个需求是，可以通过界面按钮进行图表的放大缩小。此时通过解析tree图的设置可以想到，控制图的放大缩小，只需要处理series的zoom属性即可，故会有如下代码：

```base
const zoomMax = 3
const zoomMin = 0.7

const onZoomPlus = () => {
  const opt = myChart.getOption() as any;
  myChart.setOption({
    series: [
        {
            zoom: Math.min(opt.series[0].zoom + 0.1, zoomMax),
        }
    ]
  })
}

const onZoomMinus = () => {
    const opt = myChart.getOption() as any;
  myChart.setOption({
    series: [
        {
            zoom: Math.max(opt.series[0].zoom - 0.1, zoomMin),
        }
    ]
  })
}
```

但是当实际进行操作的时候，会注意到一个问题：每次setOption执行之后，tree的展开状态就会发生变化，变成初始化的展开状态，而无法保留期间的节点展开/折叠的状态。这个问题在对应的仓库中有相关issues，例如（[#19289](https://github.com/apache/echarts/issues/19289)），有些issue甚至已经是好几年前的了，有人回复会考虑在后续版本中添加对应的功能，但是这个问题依旧没有解决。

实际上API里面会有一些提示，数据的每个节点可以定义collapsed字段，用以控制初始化的节点展开状态。而在节点展开/折叠之后，我们通过getOption获取到图表的option时，可以查看到这个过程中series中并没有添加collapsed字段，这就导致通过setOption时，option中的series实际上是最开始图表初始化时的series，所以折叠状态会被重置。

因此可以想到，解决方案之一是，在节点展开/折叠发生后，手动设置collapsed字段，使其可以保存对应的值，以便在setOption时处理正确。tree本身没有监听展开/折叠的事件，因此我们从click入手（当然，如果是其他途径进行控制的，在对应方法中进行处理）。

```base
  myChart.on('click', function (params) {
      if (params.componentType === 'series') {
          (params.data as any).collapsed = !(params.data as any).collapsed;
      }
  });
```

此时我们再进行上述提到的操作进行setOption，可以看到折叠状态正确保留。
